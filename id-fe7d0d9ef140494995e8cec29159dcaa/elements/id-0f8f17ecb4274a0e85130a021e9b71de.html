4. WebMCP in-browser ()
When the WebMCP engine fetches statistical series or metadata updates to process locally, it requests UDDP-compliant JSON payloads. This guarantees that client-side WebMCP tools enforce the exact same zero-hallucination guardrails, citations, and NSO attribution requirements as server-side channels. WebMCP sits at the browser and client runtime layer, functioning as an in-browser MCP agent adapter and client-side tool execution environment. While traditional Server-side MCP runs on NSO infrastructure (handling remote tool execution over HTTP/SSE or WebSockets), WebMCP executes directly within the client’s browser sandbox using browser capabilities like WebAssembly (Wasm), local Web Storage/IndexedDB, and standard Web APIs.
